### 2.2 做对的三件事

**第一，先跑通一个模块再复制。** 药品模块把「分页 + 关联表 + 图片上传 + 角色控制」全部覆盖了，其余七个模块基本是照着改字段。前端也一样，先把 `crudPage` mixin 抽出来，八个页面只写 `fetchList()` 和 `save()`，避免八份重复代码。

**第二，每个结论都要有证据。** 说「登录能用了」不算数，要拿出 `{"code":20000,"role":"ROLE_1"}`；说「页面正常」不算数，要截图。这个习惯直接救回了 4 个缺陷——接口全绿但页面是坏的。

**第三，把「为什么」写进注释。** 比如 Nginx 的 `^~`、Jackson 为什么要用 `BuilderCustomizer`、菜单为什么在后端算。这些地方如果不写原因，下次（或者答辩时被问）就得重新推一遍。

### 2.3 走了弯路的地方

| 弯路 | 代价 | 教训 |
| --- | --- | --- |
| 自己 new 一个 `ObjectMapper` 加 `@Primary` 想改时间格式 | 改了两次都没生效 | Boot 的自动配置已经注册过 Bean，`@ConditionalOnMissingBean` 会跳过我的；应该用 `Jackson2ObjectMapperBuilderCustomizer` |
| 页脚页码用空 `w:fldSimple` | Word 打开后空转，导出 PDF 卡死几十分钟 | 域必须有缓存结果，或者用标准三段式 fldChar |
| 用 Word COM 直接改 docs 目录下的 docx | 反复报「文档已损坏」/ 保存无权限 | 涉及 Word 自动化，先拷到 `%TEMP%` 纯英文路径再操作 |
| 想用 Element Plus 美化界面 | 差点推翻技术栈 | Element Plus 只支持 Vue 3；Vue 2 用 Element UI 2.15 已经够用 |

## 三、技术收获

1. **Spring Security 的过滤链要自己动手配过才懂。** `JwtFilter` 为什么必须放在 `UsernamePasswordAuthenticationFilter` 之前、四类失败为什么要分开处理、`STATELESS` 和关闭 CSRF 分别意味着什么，这些看书只能记住名词。

2. **MyBatis 的 `#{}` 和 `${}` 差别不是语法问题而是安全问题。** 全项目零 `${}`，参数一律占位符。

3. **前后端分离的核心是「接口契约」。** 统一返回体 `Msg`、统一分页结构、统一返回码，前端才敢用一个拦截器处理所有错误。契约一旦统一，加模块的成本极低。

4. **动态路由是权限设计的一部分。** 一开始以为路由是前端的事，做完才明白：菜单、路由、接口权限必须是同一套数据（`permission` + `role_permission`）驱动的，否则三者迟早不一致。

5. **部署不是「打包上传」这么简单。** 开发态直连 8080、生产态走 `/api` 反代，中间隔着 Nginx 的匹配规则、图片静态目录、跨域与编码。这些问题在本地开发时一个都不会出现。

## 四、不足与改进

| 不足 | 现状 | 改进方向 |
| --- | --- | --- |
| 没有并发压测 | 只有功能与界面测试 | 用 JMeter 做 50/100 并发的查询与新增，观察 Druid 连接池与响应时间 |
| 浏览器兼容性窄 | 只测 Chromium 内核 | 补 Firefox / Safari 的样式与地图兼容 |
| 界面测试未入 CI | 脚本依赖本地 Chrome 调试端口 | 换 Playwright + GitHub Actions，每次提交跑回归 |
| 安全加固不足 | 数据库用 root、无登录失败限制 | 建受限账号、加失败次数限制、加操作日志审计 |
| 地图 Key 暴露 | 前端明文（JS API 机制如此） | 控制台配 referer 白名单与配额告警 |

## 五、心得体会

这个项目最大的体会是：**「跑起来」和「能用」之间隔着一整轮验收。**

代码写完、接口通了，只完成了六成。剩下四成是：页面上的图裂没裂、时间格式对不对、换台机器部署还灵不灵、医师点进来会不会看到不该看的按钮。这些都不在需求文档里，但都是用户真实会遇到的。

另一个体会是**记录的价值**。中途踩过的坑如果只是「解决了」，下次还会再踩一遍；写成「现象—原因—处理」记下来，它才变成经验。报告里那 7 条缺陷记录，其实比 35 条通过用例更有信息量——通过说明做到位了，缺陷说明边界在哪。
