# 接口清单（后端已实现部分）

> 更新时间：2026-11-05 ｜ 端口 8080 ｜ 统一前缀 `/api`
> 返回体统一为 `Msg`：`{"code":20000,"mess":"...","data":{...}}`
> `20000` 成功、`10000` 业务失败、`10006` 未登录或 token 失效

## 认证与权限

| 方法 | 路径 | 说明 | 角色 |
| --- | --- | --- | --- |
| POST | `/api/login` | 表单 `username`/`password` 登录，返回 `token`、`tokenHead`、`utype`、`role`、`user` | 公开 |
| GET | `/api/permissions` | 当前用户菜单树（`data.permissions`） | 已登录 |

## 权限矩阵

| 操作 | 管理员 ROLE_1 | 医师 ROLE_2 |
| --- | --- | --- |
| 全部查询接口 | ✅ | ✅ |
| 药品新增 | ✅ | ✅ |
| 药品修改 / 删除 | ✅ | ❌ 10000 权限不足 |
| 其余模块新增/修改/删除 | ✅ | ❌ 10000 权限不足 |
| 图片上传 | ✅ | ✅ |

权限由后端 `@RolesAllowed` 强制，前端只负责隐藏按钮。

## 医生新增的账号规则

- 登录名：不填时按「姓名 + 手机号后 4 位」生成（如 `测试医师8888`）
- 初始口令：`123456`（BCrypt 入库）
- 角色：`utype = ROLE_2`
- 删除医师时一并删除其账号；`PUT /api/doctors/pwd/{id}` 可重置口令

## 药品与药店关联

- 新增/修改时提交 `saleIds: [1,2]`，后端整体替换 `drug_sale` 关系（先删后插）
- 列表接口用 `GROUP_CONCAT` 带出 `saleNames`
- 删除药品时先清 `drug_sale` 再删主表

## 实测结论（2026-11-05）

41 项接口用例全部通过：8 个模块 CRUD、分页、关键字查询、关联校验（挂不存在的公司/城市/药店会被拒）、
角色越权（医师改删 → 10000）、参数校验（空标题 → "标题不能为空"）、图片上传与 `/image/**` 访问、非法扩展名拒绝。
