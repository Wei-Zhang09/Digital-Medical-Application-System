# 部署说明（本机 Nginx 版）

> 目标环境按任务书是 openEuler 22.03 + Nginx 1.20.1 + MySQL 8 + JDK 17。
> 本机没有 openEuler，用 Windows 版 Nginx 1.20.1 走同一套步骤，命令与配置基本一致。

## 0. 一页速查

| 项 | 值 |
| --- | --- |
| 站点地址 | `http://127.0.0.1/#/user/login`（80 端口，地址里没有 9092） |
| Nginx | `.dev/nginx/nginx-1.20.1/`（1.20.1，与任务书一致） |
| 站点根目录 | `.dev/nginx/nginx-1.20.1/html/medical`（前端 dist） |
| 后端 jar | `backend/target/medicai-1.0-SNAPSHOT.jar`（8080） |
| 数据库 | 本机项目实例 `127.0.0.1:3307`，库 `bin_text`，root / `123456` |
| 账号 | 管理员 `admin_1` / `123456`；医师 `王小明4125` / `123456` |

## 1. 顺序不能反

1. 数据库就绪（`bash scripts/db.sh start`，已导入 `bin_text`）
2. 打后端 jar：`cd backend && mvn clean package -DskipTests`
3. 打前端 dist：`cd frontend && npm run build`（走 `.env.production`，`baseURL=/api`）
4. dist 放进 Nginx 站点目录
5. 起后端（8080），确认 `http://127.0.0.1:8080/swagger-ui.html/` 能开
6. 起 Nginx（80），`nginx.exe -t` 通过后再 `nginx.exe`

## 2. 装 Nginx

```bash
mkdir -p .dev/nginx && cd .dev/nginx
curl -sSL -o nginx.zip https://nginx.org/download/nginx-1.20.1.zip
unzip -q nginx.zip            # 解出 nginx-1.20.1/
```

## 3. 配置

`deploy/nginx.conf` 是版本库里的配置，`scripts/deploy.sh` 会把它拷到
`.dev/nginx/nginx-1.20.1/conf/nginx.conf`。核心就两个反代：

```nginx
location ^~ /api/   { proxy_pass http://127.0.0.1:8080/api/; }
location ^~ /image/ { proxy_pass http://127.0.0.1:8080/image/; }
```

### 踩过的坑：`^~` 不能省

一开始写的是 `location /image/`，结果所有图片都 404，`/api/xxx.png` 也一样。
原因是后面还有一条正则 location：

```nginx
location ~* \.(js|css|png|jpg|jpeg|gif|ico|...)$ { expires 7d; }
```

**Nginx 的匹配顺序是：前缀匹配命中后，还会继续尝试正则 location，正则优先。**
所以 `/image/xxx.jpg` 被静态资源正则抢走，Nginx 去 `html/medical` 里找这个文件，自然 404。
给前缀加 `^~`（命中后不再尝试正则）就解决了。

这个坑只有真机验收才暴露得出来——接口测试全绿，但页面上的图全是裂的。

## 4. 前端地址配置（不用改代码）

| 文件 | 用途 | 值 |
| --- | --- | --- |
| `.env.development` | `npm run serve` 开发态 | `VUE_APP_API_BASE=http://localhost:8080/api`，`VUE_APP_IMAGE_BASE=http://localhost:8080` |
| `.env.production` | `npm run build` 生产态 | `VUE_APP_API_BASE=/api`，`VUE_APP_IMAGE_BASE=`（同源） |

讲师手册里强调过「部署时最容易漏的是 baseURL」——把地址写死在 `request.js` 里，
打完包忘了改回来，或者改了忘了改回去，都是常见事故。用 `.env.*` 分离后构建产物天然正确，
不用手工改代码。

## 5. 数据库图片地址

种子数据里 `drug.drug_img` 原本写死 `http://localhost:8080/image/xxx.jpg`，
换机器或部署后浏览器会去访问访问者自己的 8080，图必然裂。
`sql/image_url_relative.sql` 把前缀改成相对路径 `/image/`：

```sql
UPDATE drug SET drug_img = REPLACE(drug_img, 'http://localhost:8080/image/', '/image/')
WHERE drug_img LIKE 'http://localhost:8080/image/%';
```

开发态由 `.env.development` 拼回 8080，生产态由 Nginx 反代，两边都不用改代码。

## 7. 常见问题

| 现象 | 先看 |
| --- | --- |
| 页面能开、接口 404 | `proxy_pass` 末尾的 `/api/` 有没有保留 |
| 图片全裂 | `location` 有没有加 `^~`；后端 `uploads/` 有没有图 |
| 登录一直转圈 | 后端 8080 是否起来；`.env.production` 的 `VUE_APP_API_BASE` 是否为 `/api` |
| 80 端口起不来 | `netstat -ano | grep ":80 "` 看占用；本机 fastgithub 之类会抢 80 |
| 改了配置不生效 | 必须 `nginx.exe -s reload`，`nginx -t` 要在 nginx 目录里执行 |
| 中文乱码 | 库字符集 utf8mb4 + JDBC `characterEncoding=utf8` |
