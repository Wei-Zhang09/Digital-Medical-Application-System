# 答辩提纲

> 演示时长 8–10 分钟，讲完留时间问答。原则：每一步只做一次成功操作，不现场排错。

## 一、开场 30 秒

> 「我做的是慧医数字医疗应用系统，Spring Boot + Vue 前后端分离的管理后台，9 个模块、两种角色，另外完成了数据面板和销售地点地图两个扩展功能。今天不讲功能清单，讲清一条链路、两处扩展、一次部署和一轮测试。」

## 三、预设问答

### Q1：为什么用 JWT 不用 Session？

前后端分离、要部署到 Nginx 后面，Session 需要共享存储。JWT 无状态，服务端不存会话，横向扩展不用考虑粘性。代价是 token 签发后 24 小时内无法主动失效，只能靠过期；如果要强制下线，需要加黑名单。

### Q2：菜单为什么要后端返回，前端写死不更简单？

菜单就是权限的可视化。前端写死的话，用户改一下本地存储就能看到不该看的入口。虽然后端接口还有 `@RolesAllowed` 兜底，但让「看到的」和「能做的」由同一个数据源决定，才不会出现「菜单有、点了 403」的割裂。

### Q3：药品和药店为什么用中间表，不在药品表里存一个药店 id？

一种药可以在多家药店卖，一家药店也卖多种药，是多对多。存一个 id 只能表达一对一。中间表 `drug_sale` 还能带扩展字段（比如上架时间、库存），后续要加不用改主表。

### Q4：修改药品时为什么全部删掉重插，不比对差异？

比对差异要写「哪些新增、哪些删除、哪些保留」三套逻辑，代码量和出错面都更大。整体替换在一个事务里，语义简单、结果确定，数据量小的时候是更划算的选择。

### Q5：怎么保证权限不被绕过？

三层：菜单按 `role_permission` 下发（看不见入口）、`JwtFilter` 校验每个请求的 token（身份）、`@RolesAllowed` 拦截具体方法（角色）。前端隐藏按钮只是体验，不作为安全手段。测试里专门有一条用例：医师直接调 `PUT /api/drugs/{id}`，返回 `10000 权限不足`。

### Q6：测试怎么做的？发现了什么问题？

四层：单元测试 17 条（JWT、菜单树、药品关联）、接口用例 35 条、界面端到端 5 组 32 项断言、部署验收 5 条。

一共发现 7 个缺陷，**其中 4 个是「接口全绿、界面是坏的」**：登录后红屏遮罩、药品图全是占位、时间格式带 T 折行、部署后图片全 404（Nginx 正则抢了 `/image/`）。这 4 个只有用真实浏览器看页面才发现得了——所以测试必须分接口层和界面层两层。

### Q7：Nginx 那条 `^~` 是怎么回事？

`location /image/` 是前缀匹配，但后面还有一条正则 location 匹配 `.png|.jpg` 结尾的请求。**Nginx 的规则是前缀命中后还会尝试正则，正则优先**，所以图片请求被静态资源正则抢走，去 dist 目录找文件，自然 404。加 `^~` 表示「命中后不再尝试正则」才解决。

### Q8：部署时最容易出错的地方是什么？

baseURL。如果前端把接口地址写死成 `http://localhost:8080/api`，打完包部署到服务器，观众打开页面时浏览器会去访问**观众自己电脑**的 8080，接口全失败。我用 `.env.development` / `.env.production` 把开发和生产地址分开，构建产物天然是 `/api`，不靠人记得改回来。

### Q9：如果让你再加一个模块，要改哪些地方？

后端各层各加一个类（controller/service/mapper + XML/entity/param），前端加一个页面和 api 文件，数据库加一张表，最后在 `permission` 表插一条记录、在 `role_permission` 给管理员授权。必备材料模块就是最小的模板，照着复制最快。

### Q10：这个系统最大的不足是什么？

三个：没做并发压测（单机演示场景）；只测了 Chromium 内核；界面测试脚本依赖本地 Chrome 调试端口，没接 CI。上生产前还要把数据库账号从 root 换成受限账号、给高德 Key 加 referer 限制、加登录失败次数限制和操作日志。
