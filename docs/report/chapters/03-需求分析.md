# 3. 需求分析

## 3.1 整体业务流程

系统的业务主线只有一条：**登录 → 按角色拿到菜单 → 在模块里做增删改查**。

```
用户打开登录页
   │
   ├─ 输入用户名/口令 → POST /api/login
   │        │
   │        ├─ 校验失败 → 返回 10000「用户名或密码错误」，停留登录页
   │        └─ 校验通过 → 签发 JWT（载荷含 id/uname/role），前端存 localStorage
   │
   ▼
前端带着 token 请求 GET /api/permissions
   │
   ├─ token 无效/过期 → 返回 10006 → 清本地状态，回登录页
   └─ 有效 → 后端按 role 查 role_permission → 组装菜单树返回
   │
   ▼
前端 routeParse 把菜单树翻译成路由，动态 addRoute
   │
   ▼
用户点击菜单进入模块 → 列表查询（分页 + 关键字）
   │
   ├─ 管理员：可新增/修改/删除，弹窗表单 + 二次确认
   └─ 医师：只能查询；药品可新增，改删按钮不显示，且后端 @RolesAllowed 会拒绝越权请求
```

## 3.2 功能性需求分类

| 功能类别 | 子功能 | 使用角色 |
| --- | --- | --- |

## 3.3 关键用例

### 3.3.1 用例一：用户登录

| 项 | 内容 |
| --- | --- |
| 用例名称 | 用户登录 |
| 参与者 | 管理员、医师 |
| 优先级 | 高 |
| 前置条件 | 数据库中存在账号，口令以 BCrypt 密文存储 |
| 输入 | 用户名、口令 |
| 操作 | 输入用户名与口令，点击「登录」 |
| 输出 | 成功：返回 token 与角色，跳转首页并按角色渲染菜单；失败：提示「用户名或密码错误」 |
| 异常流 | 用户名为空或口令错误 → 10000；未登录访问受保护接口 → 10006；token 被篡改 → 10006 |

### 3.3.2 用例二：新增药品（含图片与关联药店）

| 项 | 内容 |
| --- | --- |
| 用例名称 | 新增药品 |
| 参与者 | 管理员、医师 |
| 优先级 | 高 |
| 前置条件 | 已登录；已存在可关联的销售地点 |
| 输入 | 药名、药品成分、药品功能、图片文件（≤1MB，jpg/png/gif）、关联药店 id 列表 |
| 操作 | 点击「新增药品」→ 填写表单 → 选择药店 → 上传图片 → 保存 |
| 输出 | 列表新增一条记录，图片可预览，销售药店列显示关联药店名称 |
| 异常流 | 药名为空 → 「药名不能为空」；图片超 1MB 或格式不支持 → 前端拦截并提示；关联药店不存在 → 「销售地点不存在：xxx」 |

### 3.3.3 用例三：医师越权修改药品

| 项 | 内容 |
| --- | --- |
| 用例名称 | 医师尝试修改药品（权限校验） |
| 参与者 | 医师 |
| 优先级 | 中（安全用例） |
| 前置条件 | 医师已登录 |
| 操作 | 直接调用 `PUT /api/drugs/{id}`（绕过界面） |
| 输出 | 返回 `code=10000`，提示「权限不足，无法访问该资源」，数据不变 |
| 说明 | 界面上医师看不到「编辑」按钮，但真正的拦截在后端 `@RolesAllowed`，前端隐藏只是体验优化 |

## 3.4 非功能性需求

### 3.4.1 用户界面需求

| 需求名称 | 详细要求 |
| --- | --- |
| 主色调 | 医疗青绿（#13b7a5）+ 深色侧栏（#1f2d3d），与登录背景图统一 |
| 布局 | 左侧 240px 固定菜单、顶部 64px 信息栏、右侧内容区自适应 |
| 交互一致性 | 所有列表页统一「搜索栏 → 表格 → 分页」，新增/修改统一用弹窗，删除统一二次确认 |
| 反馈 | 操作成功/失败统一用顶部消息条；危险操作（删除、重置口令）必须二次确认 |
| 可读性 | 长文本列 `show-overflow-tooltip` 悬浮显示全文；时间统一 `yyyy-MM-dd HH:mm:ss` |

### 3.4.2 性能需求

| 项 | 要求 | 实现 |
| --- | --- | --- |
| 响应时间 | 常规查询 ≤1 秒 | 单机实测列表查询 100ms 级；PageHelper 分页避免全表返回 |
| 数据量 | 单表万级记录可正常分页 | 分页 + 关键字模糊查询 + 必要索引（主键、`uname` 唯一索引） |
| 连接池 | 并发下不耗尽连接 | Druid 初始 5、最大 20、maxWait 60s |
| 上传限制 | 单图 ≤1MB | 后端 multipart 上限 1MB，前端 `before-upload` 预校验 |

### 3.4.3 安全需求

| 项 | 要求 | 实现 |
| --- | --- | --- |
| 口令存储 | 不得明文 | BCrypt 加盐哈希，`pwd` 字段只存密文 |
| 身份凭证 | 无状态、可校验 | JWT（HS256），有效期 24 小时，签名密钥服务端持有 |
| 权限控制 | 服务端强制，不能只靠前端隐藏 | `@RolesAllowed` + Spring Security 过滤链 |
| SQL 注入 | 参数化查询 | MyBatis `#{}` 占位符，禁止 `${}` 拼接 |
| 越权 | 菜单与接口双重校验 | 菜单按 `role_permission` 下发；接口按角色注解拦截 |

### 3.4.4 质量需求

| 属性 | 要求 |
| --- | --- |
| 正确性 | 关键业务（药品与药店关联、医师与账号联动）有单元测试覆盖 |
| 健壮性 | 非法输入返回统一 `10000` 与可读提示，不抛 500 给用户 |
| 可维护性 | 后端严格分层（controller/service/mapper/domain），前端列表页逻辑抽 mixin |
| 可部署性 | 一条命令构建、一份配置部署，开发与生产地址通过 `.env` 分离 |
| 可扩展性 | 新增一个模块 = 各层各加一个类 + 前端一个页面 + 一条 permission 记录 |
