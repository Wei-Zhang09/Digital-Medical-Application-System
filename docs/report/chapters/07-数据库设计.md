# 7. 数据库设计

## 7.1 数据库环境

| 项 | 值 |
| --- | --- |
| 数据库系统 | MySQL 8.0.41（InnoDB） |
| 数据库名 | `bin_text` |
| 字符集 / 排序规则 | utf8mb4 / utf8mb4_general_ci |
| 连接方式 | JDBC + Druid 连接池，`characterEncoding=utf8` |
| 表数量 | 17 张（16 张业务表 + 1 张权限关系表 `role_permission`） |
| 初始化脚本 | `sql/bin_text.sql`（含种子数据）、`sql/sale_ext.sql`（地图扩展）、`sql/reset_pwd.sql`、`sql/image_url_relative.sql` |

## 7.2 逻辑结构

核心实体与关系：

| 关系 | 类型 | 说明 |
| --- | --- | --- |
| account ↔ doctor | 1 : 1 | 一个医师对应一个登录账号，`doctor.account_id` 指向 `account.id`；删除医师连带删账号 |
| doctor → doctor_level | N : 1 | 医师属于某个职称（主任医师/普通医师/实习医师） |
| doctor → treat_type | N : 1 | 医师属于某个科室（肩部/膝部/踝部/腰部等） |
| drug ↔ sale | M : N | 药品可在多家药店销售，通过 `drug_sale` 关联 |
| company_policy → drugcompany | N : 1 | 公司政策挂靠一家医药公司 |
| medical_policy → city | N : 1 | 医保政策按城市生效 |
| permission ↔ role | M : N | 菜单权限通过 `role_permission(roleName, per_id)` 授予角色 |
| permission → permission | 自关联 | `pid` 指向父菜单，构成树 |

## 7.4 安全性设计

| 措施 | 说明 |
| --- | --- |
| 口令加密 | `pwd` 只存 BCrypt 密文（`$2a$10$...`），登录时由 `BCryptPasswordEncoder` 比对，库中不出现明文 |
| 参数化查询 | 所有 SQL 用 MyBatis `#{}` 占位符，未使用 `${}` 拼接，避免 SQL 注入 |
| 最小权限 | 应用使用 `root` 仅为课程演示方便；生产环境应建专用账号，只授予 `bin_text` 库的 CRUD 权限 |
| 权限分层 | 菜单可见性由 `role_permission` 控制，接口访问由 `@RolesAllowed` 控制，两者都不可绕过 |
| 事务 | 涉及多表的操作（新增医师建账号、药品关联表替换、删除清关系）均加 `@Transactional(rollbackFor = Exception.class)` |
| 敏感信息 | JWT 签名密钥在服务端常量中，未下发前端；前端只持有 token 本身，24 小时过期 |
| 备份 | 演示环境用 `bin_text.sql` 全量脚本作为基线，改动数据前可重新导入 |
