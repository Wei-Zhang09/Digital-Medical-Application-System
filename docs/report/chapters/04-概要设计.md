# 4. 概要设计

## 4.1 系统体系结构

系统采用前后端分离的三层结构，前端只负责渲染与交互，所有业务规则与权限判断都在后端。

| 层次 | 组成 | 职责 |
| --- | --- | --- |
| 表现层 | Vue 2 + Element UI + Vue Router + Vuex | 页面渲染、表单校验、路由守卫、请求封装、按角色渲染菜单 |
| 接入层 | Nginx（生产）/ vue-cli dev server（开发） | 托管静态资源；把 `/api/`、`/image/` 反代到后端；开发态直连 8080 |
| 应用层 | Spring Boot + Spring Security + MyBatis | 认证鉴权、业务逻辑、参数校验、统一返回体、分页、文件上传 |
| 数据层 | MySQL 8 + Druid 连接池 | 17 张表存储主数据与权限数据 |

调用链：`浏览器 → Nginx → Spring Boot（Controller → Service → Mapper → MySQL）`，返回体统一为 `Msg{code, mess, data}`。

## 4.4 接口设计

### 4.4.1 统一约定

| 项 | 约定 |
| --- | --- |
| 前缀 | 所有业务接口以 `/api` 开头 |
| 认证 | 请求头 `Authorization: Bearer <token>` |
| 返回体 | `{"code": 20000, "mess": "操作成功", "data": {...}}` |
| 返回码 | `20000` 成功；`10000` 业务失败（含权限不足、校验失败）；`10006` 未登录或 token 失效 |
| 分页 | `GET /{模块}/{pageNum}/{pageSize}?关键字=`，返回 `data.xxxPageInfo{pageNum,pageSize,total,pages,list}` |
| 方法语义 | GET 查询、POST 新增、PUT 修改、DELETE 删除 |
| 时间格式 | `yyyy-MM-dd HH:mm:ss` |

### 4.4.2 外部接口

| 接口 | 说明 | 输入 | 输出 |
| --- | --- | --- | --- |
| `POST /api/login` | 登录（表单提交） | `username`、`password` | token、tokenHead、utype、role、user |
| `POST /api/upload` | 药品图片上传（multipart） | `file`（≤1MB，jpg/png/gif） | `data.url = /image/xxx.png` |
| `GET /image/**` | 图片静态访问 | 文件名 | 图片二进制 |
| 高德地图 JS API | 销售地点地图展示 | Key + 安全密钥 | 地图瓦片与逆地理编码结果 |

### 4.4.3 内部接口

内部接口即 8 个模块的 REST 接口，明细见《接口清单.md》。此处给出汇总：

| 模块 | 查询 | 新增 | 修改 | 删除 | 附加 |
| --- | --- | --- | --- | --- | --- |
| 菜单 | `GET /api/permissions` | — | — | — | 按角色返回树 |
| 医生 | `GET /api/doctors/{pn}/{size}` | POST | PUT | DELETE | `/levels`、`/types`、`/pwd/{id}` |
| 医药公司 | `GET /api/companies/{pn}/{size}` | POST | PUT | DELETE | `/all` |
| 公司政策 | `GET /api/companyPolicies/{pn}/{size}` | POST | PUT | DELETE | 需 companyId |
| 城市 | `GET /api/cities/{pn}/{size}` | POST | — | DELETE | `/all` |
| 医保政策 | `GET /api/medicalPolicies/{pn}/{size}` | POST | PUT | DELETE | 需 cityId |
| 销售地点 | `GET /api/sales/{pn}/{size}` | POST | PUT | DELETE | `/all`、经纬度字段 |
| 药品 | `GET /api/drugs/{pn}/{size}` | POST | PUT | DELETE | `/{id}` 详情、saleIds |
| 必备材料 | `GET /api/materials/{pn}/{size}` | POST | PUT | DELETE | — |
| 数据面板 | `GET /api/dashboard` | — | — | — | 角色 1、2 |

## 4.5 部署设计

```
                 ┌─────────────────────────────┐
   浏览器 ────────▶│  Nginx 1.20.1 : 80          │
                 │  ├─ /            → dist 静态 │
                 │  ├─ ^~ /api/     → 127.0.0.1:8080/api/
                 │  └─ ^~ /image/   → 127.0.0.1:8080/image/
                 └──────────────┬──────────────┘
                                │
                 ┌──────────────▼──────────────┐
                 │  Spring Boot jar : 8080      │
                 │  uploads/ 存放上传的药品图片  │
                 └──────────────┬──────────────┘
                                │ JDBC（Druid）
                 ┌──────────────▼──────────────┐
                 │  MySQL 8.0 : 3306/3307       │
                 │  digital_medical_application_system（17 张表）          │
                 └─────────────────────────────┘
```

部署要点：

1. 前端构建前由 `.env.production` 把接口地址设为 `/api`，产物里不含任何 `localhost:8080`，换机器不会指错。
2. Nginx 的 `/api/`、`/image/` 前缀必须加 `^~`，否则会被静态资源正则 location 抢走导致 404（本项目实际踩过）。
3. 后端 jar 的工作目录下必须有可写的 `uploads/`，`/image/**` 映射到该目录。
4. 验收以 80 端口访问，地址中不出现 9092（开发端口）。
