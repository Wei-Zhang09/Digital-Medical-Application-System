# 1. 项目立项

## 1.1 项目背景

医疗机构的日常运转依赖大量分散的信息：医生档案在人事系统、药品目录在药房台账、销售网点在 Excel、医保与公司政策散落在文件柜里。这些信息彼此不连通，导致三个具体问题：

1. **同一份数据多处维护**：药品在药房台账和采购单里各有一份，名称与图片对不上。
2. **权限没有边界**：台账在共享盘里，谁都能改，改动没有记录，也无法按角色限制。
3. **看不见全局**：管理者想知道「有多少医师、多少药品、多少药店」只能人工数。

本项目要做的，是把这些主数据收进一个统一的管理后台：一个数据库、一套接口、一个按角色区分的界面，让管理员集中维护、医师按权限查询。

项目定位是软件工程综合实训作品，技术栈与课程任务书保持一致（Spring Boot + Vue + MySQL），并在基础增删改查之上完成数据面板与地图两个扩展功能。

## 1.2 客户与最终用户

| 角色 | 说明 | 在本系统中的诉求 |
| --- | --- | --- |
| 客户（需求提出方） | 医院信息科（课程中由指导教师扮演） | 主数据集中管理、按角色控制权限、可部署可验收 |
| 最终用户：管理员 | 信息科运维人员 | 维护医药公司、销售地点、城市、药品、医保政策、公司政策、医生、必备材料全部数据 |
| 最终用户：医师 | 临床医生 | 查询药品、医保政策、公司政策、必备材料；可新增药品，但不能修改和删除 |
| 非目标用户 | 患者 | 账号表里保留了 `utype=3` 的患者类型，但本系统没有患者端功能，不做演示 |

## 1.3 产品范围

### 1.3.1 基础功能（必做）

| 功能类别 | 子功能 |
| --- | --- |
| 登录与权限 | 用户名口令登录、JWT 签发与校验、按角色下发菜单、接口级角色控制 |
| 医生信息管理 | 医师查询、新增（同步建账号）、修改、删除、重置口令 |
| 医药公司管理 | 查询、新增、修改、删除 |
| 医药公司政策 | 查询、新增、修改、删除（挂靠医药公司） |
| 城市信息管理 | 查询、新增、删除 |
| 医保政策管理 | 查询、新增、修改、删除（按城市生效） |
| 销售地点管理 | 查询、新增、修改、删除 |
| 药品信息管理 | 查询、新增、修改、删除、图片上传、关联药店 |
| 必备材料管理 | 查询、新增、修改、删除 |

### 1.3.2 扩展功能（本项目已完成）

| 功能 | 内容 |
| --- | --- |
| 首页数据面板 | 医师/公司/药品/药店四个数量、医师职称柱状图、科室饼图、最新资讯列表 |
| 销售地点地图 | 列表/地图切换、地图打点、点击标记修改、管理员点「新增」后在地图上落点并逆地理编码出地址 |

### 1.3.3 明确不做（范围外）

- 患者端（挂号、就诊、处方流转）
- 药品库存与进销存、采购单与结算
- 消息通知、审批流
- 移动端适配（系统定位是桌面端后台管理）

范围划到这里的原因：课程周期内要保证「每条链路都真的能跑通」，而不是铺开一堆半成品。扩展功能之所以选数据面板和地图，是因为它们能复用已有的主数据，不引入新的业务实体。
