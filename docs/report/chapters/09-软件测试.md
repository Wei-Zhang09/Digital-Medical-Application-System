# 9. 软件测试

## 9.1 测试计划

### 9.1.1 测试范围

| 层次 | 范围 | 方式 |
| --- | --- | --- |
| 单元测试 | 服务层核心逻辑（JWT、菜单树、药品关联） | JUnit 5 + Mockito，17 条 |
| 接口测试 | 全部 REST 接口的正常与异常路径 | Python 脚本直连 HTTP，35 条 |
| 界面测试 | 登录、动态菜单、9 个业务页面、地图、数据面板 | puppeteer 驱动真实浏览器，5 组共 32 项断言 |
| 部署验收 | Nginx 80 端口站点 | 按任务书「验收五下」逐条验证 |

不在范围内：并发压力测试、移动端适配、IE 兼容性、安全渗透测试。

### 9.1.2 测试环境

| 项 | 值 |
| --- | --- |
| 操作系统 | Windows 11 |
| 后端 | JDK 17.0.19 + Spring Boot 2.5.3（jar 方式运行，8080） |
| 前端 | Node 22.13.0 + Vue CLI 5.0.9，开发态 9092 / 部署态 80 |
| 数据库 | MySQL 8.0.41（127.0.0.1:3307，库 `digital_medical_application_system`） |
| 反向代理 | Nginx 1.20.1 |
| 浏览器 | Chrome 145（Chromium）、Edge |

### 9.1.3 测试策略

1. **先接口后界面**：接口保证数据正确，界面保证「人能看到正确的数据」。
2. **正常路径 + 异常路径成对**：每个正向用例配一条异常用例（越权、空值、不存在、非法格式）。
3. **每个结论都要有可复现的证据**：接口用例输出实际返回码，界面用例截图存 `docs/report/screenshots/`。
4. **回归看证据不看印象**：修完缺陷必须重跑对应脚本，脚本 PASS 才算修复。

## 9.4 测试总结

### 9.4.1 结论

- 35 条接口用例、17 条单元测试、32 项界面断言、5 条部署验收，**全部通过**。
- 系统满足需求规格：8 个模块的增删改查、按角色区分的菜单与接口权限、图片上传、数据面板与地图两项扩展均可用。
- 部署形态可用：80 端口访问、静态资源与接口分离、图片可正常显示。

### 9.4.2 有价值的经验

**接口全绿不等于系统可用。** 本轮 7 个缺陷里有 4 个属于「接口返回正常、界面上是坏的」：

| 缺陷 | 接口表现 | 界面表现 |
| --- | --- | --- |
| BUG-01 红屏遮罩 | 登录返回 20000 | 页面被 webpack 错误遮罩盖住，无法操作 |
| BUG-03 药品图空 | 列表接口返回 url 正常 | 图片全显示占位图标 |
| BUG-04 时间折行 | 返回 `2021-11-18T17:34:02` 合法 | 表格列被撑开折行，可读性差 |
| BUG-05 部署图片 404 | `/api` 全部正常 | `/image/` 被 Nginx 正则抢走，图全裂 |

所以测试必须分两层：接口层验证数据与权限，界面层用真实浏览器验证「人看到的东西」。只跑接口测试，这 4 个缺陷一个都发现不了。
