# 8. 编码与单元测试

## 8.1 编码规范与工程约定

| 项 | 约定 |
| --- | --- |
| 后端分层 | `controller → service → service.impl → mapper(+XML) → domain(entity/dataobject/dto/model/param)` |
| 实体四层 | `entity` 与表字段一一对应；`dataobject`（AccountDo）继承 entity 补库操作字段；`dto` 实现 `UserDetails`；`model` 是返回前端的视图对象；`param` 是入参 |
| 统一返回 | 所有接口返回 `Msg`，禁止直接返回实体或裸 Map |
| 异常处理 | 业务异常抛 `IllegalArgumentException`，由 `GlobalExceptionHandler` 转成 `10000`；参数校验由 `@Validated` 拦截 |
| 分页 | 统一 `PageHelper.startPage` + `PageUtil.toPageBean`，返回 `data.xxxPageInfo` |
| 事务 | 多表写操作加 `@Transactional(rollbackFor = Exception.class)` |
| 前端分层 | `api/`（接口）、`views/`（页面）、`mixins/crudPage.js`（列表页公共逻辑）、`utils/`（请求与提示）、`store/`（登录态与菜单） |
| 列表页复用 | 8 个页面共用 `crudPage` mixin：分页、搜索、弹窗开关、删除确认都只写一次，页面只实现 `fetchList()` 与 `save()` |
| 命名 | 后端包名 `com.qst.medical`；前端目录名沿用官方素材的拼写（如 `medical-managerment-system`、`DurgMapper.xml`），不改动以免与资料对不上 |
| 注释 | 类与方法写中文注释说明「为什么这么做」，尤其是踩过坑的地方（如 Nginx `^~`、Jackson 自定义器） |

## 8.3 单元测试

### 8.3.1 测试策略

- 使用 JUnit 5 + Mockito，只测服务层逻辑，Mapper 用 `@Mock` 隔离，不依赖数据库。
- 覆盖三类最容易出错的逻辑：JWT 的签发与校验、菜单树的递归组装、药品与关联表的多表操作。
- 断言不只看返回值，还验证「调用了哪个方法、参数是什么、顺序对不对」（`verify` + `inOrder`）。

### 8.3.3 单元测试发现的缺陷

| 缺陷 | 现象 | 原因 | 修复 |
| --- | --- | --- | --- |
| BUG-06 | `resolveToken("Basic xxx")` 返回原字符串而不是 null | 原实现只在匹配 `Bearer ` 时裁剪，否则原样返回，等于把其它认证方案的凭据当 JWT 处理 | 改为只认 `Bearer ` 前缀，其余返回 null；空 token 也返回 null |

这条缺陷是写单测时才暴露的：接口层一直没出错（前端只发 Bearer），但逻辑上留了一个不该开的口子。
